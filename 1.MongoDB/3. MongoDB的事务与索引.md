## WriteConcern& Journal
### writeConcern
决定一个写操作落到多少节点上才算成功。
* 0: 发起写操作即成功
* 1～集群最大节点数：写操作需要被多少节点复制才算成功
* majority：写操作需要被复制到大多数节点才算成功
写操作会等待设定节点数全部返回后才会返回
### Journal
* true：写操作落到Journal文件中才算成功
* false ：写操作到达内存即算成功

### ReadPreference解决从哪里读

* primary：只读主节点 --用户下单后马上查询详情页
* primaryPreferred：优先主节点，如主节点不可用选择从节点 -- 用户查询自己的历史订单
* secondary：只选择从节点 -- 生成某些报表
* secondaryPreferred：优先从节点，如果从节点不可用再选择主节点
* nearest：选择ping通的最近的节点 --用户上传的图片分发全世界，让各地用户就近读取
### ReadConcern决定什么样的数据可以读
* available：读取所有可用的数据
* local：读取所有可用且属于当前分片的数据
* majority：读取大多数节点上提交完成的数据 -- MVCC实现，保证读取的是一个被大多数节点确认过的快照，类似于read committed级别
* linearizable：可线性化读取文档
* snapshot：读取最近快照中的数据

## 索引机制

### 索引格式
```sql
db.human.createIndex({firstName: 1, lastName: 1, gender: 1, age: 1})
```
索引同样遵循最左匹配原则，以上索引的全部前缀包括：

• {firstName: 1}

• {firstName: 1, lastName: 1}

• {firstName: 1, lastName: 1, gender: 1}

### MongoDB的索引类型：
单键索引/组合索引/多值索引/地理位置索引/全文索引/TTL索引/部分索引/哈希索引

单键索引：
```sql
// 对 name 字段创建升序索引 
db.users.createIndex({ name: 1 })
```

复合索引：
```sql
// 对 age 升序、name 降序创建复合索引 
db.users.createIndex({ age: 1, name: -1 })
```

唯一索引：
```sql
// 创建唯一索引，确保 email 不重复 
db.users.createIndex({ email: 1 }, { unique: true })
```
组合索引：
``db.members.find({ gender: “F”， age: {$gte: 18}}).sort(“join_date:1”)``

最佳方式应遵循ESR原则：
先精确查找，再把排序放中间。最后是范围查询
```javascript
db.members.createIndex({ gender: 1, join_date: 1, age: 1 })
```
### MongoDB索引的常用选项
* name: 指定索引名称，不指定自动生成
  db.users.createIndex({ age: 1 }, { name: "age_index" })
* unique：创建唯一索引
* sparse：只索引包含该字段的文档
  ``db.users.createIndex({ email: 1 }, { sparse: true })``

### MongoDB 索引信息的展示
```javascript
[
  {
    "v": 2,                   // 索引版本（通常为2，对应MongoDB 3.0+）
    "key": { "_id": 1 },      // 索引键：字段及排序方向（1为升序，-1为降序）
    "name": "_id_",           // 索引名称（自动生成或自定义）
    "ns": "test.users"        // 索引所属的命名空间（数据库.集合）
  },
  {
    "v": 2,
    "key": { "name": 1, "age": -1 },  // 复合索引：name升序，age降序
    "name": "name_1_age_-1",          // 自动生成的复合索引名称
    "ns": "test.users"
  },
  {
    "v": 2,
    "key": { "email": 1 },
    "name": "email_unique",
    "ns": "test.users",
    "unique": true                   // 唯一索引标记
  },
  {
    "v": 2,
    "key": { "createdAt": 1 },
    "name": "ttl_index",
    "ns": "test.sessions",
    "expireAfterSeconds": 86400      // TTL索引：过期时间（秒）
  }
]
```

### 索引Demo
使用教程中导入的Mock collection：

1. 创建索引：
``db.Mock.createIndex({userId:1, orderDate:1})``
2. 查看索引：
```json
[
  { v: 2, key: { _id: 1 }, name: '_id_' },
  {
    v: 2,
    key: { userId: 1, orderDate: 1 },
    name: 'userId_1_orderDate_1'
  }
]
```
3. 使用索引查询：
   ``db.Mock.find({userId: 3573, orderDate: {$gte: new Date("2019-01-01")}}).sort({orderDate: 1})``
4. 索引查询解析：
   ``db.Mock.find({userId: 3573, orderDate: {$gte: new Date("2019-01-01")}}).sort({orderDate: 1}).explain("executionStats")``
   
```json

          userId: 1,
          orderDate: 1
        },
        indexName: 'userId_1_orderDate_1',
        isMultiKey: false,
        multiKeyPaths: {
          userId: [],
          orderDate: []
}
```
